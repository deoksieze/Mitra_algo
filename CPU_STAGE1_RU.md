# Этап 1: работающий CPU-детектор

**После этапа 2:** команды запуска и формат результатов сохранены. Исходники разделены на модули, данные переведены в SoA/CSR; актуальная карта и контракт backend — в [CPU_STAGE2_RU.md](CPU_STAGE2_RU.md).

Добавлен самостоятельный C++17-конвейер для поиска частичных симметрий без MATLAB, Eigen, libigl и CUDA. Поддерживается один выбранный вариант: жёсткие преобразования (поворот + сдвиг) и отражения относительно плоскости, масштаб равен 1. Есть CLI, экспорт промежуточных данных, синтетические модели с известным ответом и локальный интерактивный viewer.

Исторические `Mesh.cpp`, `SymmetryDetector.cpp` и MATLAB-файлы удалены при очистке после этапа 8; доступны в истории Git. Новое ядро — исправленный CPU-reference по общей схеме существующего проекта, а не побитовое воспроизведение его MATLAB-результатов. Сравнение со старым приложением пока невозможно: его зависимости отсутствуют. Работоспособность нового пути проверяется независимыми геометрическими случаями.

## Сразу посмотреть готовый результат

В текущем рабочем каталоге уже созданы:

- `outputs/reflection/viewer.html`: два зеркальных объекта, гипотеза 0 — искомая плоскость;
- `outputs/rigid/viewer.html`: поворот и сдвиг, гипотеза 0 — искомое преобразование;
- `outputs/partial/viewer.html`: зеркальная пара и посторонний компонент; гипотеза 0 покрывает примерно 54% площади всей модели.

Открыть `viewer.html` в обычном браузере. Это автономный файл, интернет и JavaScript-библиотеки не нужны. Если VS Code работает на удалённой машине, удобнее запустить сервер:

```bash
cd /home/ruslan/projects/SymmetryDetection
python3 -m http.server 8765 --bind 127.0.0.1 --directory outputs
```

В VS Code открыть вкладку **Ports / Порты**, перенаправить порт 8765 и открыть адрес перенаправленного порта с путём `/reflection/viewer.html` (либо `/rigid/viewer.html`, `/partial/viewer.html`). На той же машине адрес — `http://localhost:8765/reflection/viewer.html`. Сервер остановить Ctrl+C.

В viewer:

- перетаскивание вращает модель; колесо меняет масштаб; Shift + перетаскивание сдвигает;
- список выбирает гипотезу; поверхность, выборка, фильтрация и пары переключаются отдельно;
- зелёные/оранжевые точки показывают проверенные стороны A/B;
- «Показать T(сторона A)» накладывает преобразованные точки на сторону B;
- можно загрузить другой `result.json` через кнопку выбора файла без перезапуска страницы.

Viewer не запускает детектор: параметры расчёта меняются в CLI. Это новое средство просмотра результатов; старый NanoGUI-viewer не восстанавливался.

## Сборка

Достаточно CMake ≥3.16 и компилятора C++17. Python 3 нужен только для генератора моделей, создания HTML и интеграционных тестов; сторонних Python-пакетов нет.

```bash
cd /home/ruslan/projects/SymmetryDetection
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
ctest --test-dir build --output-on-failure
```

Цель `symmetry_cpu_cli` использует явный список исходников. Старые конфликтующие `.cpp` и `cmake/LegacyCMakeLists.txt` удалены при очистке после этапа 8; доступны в истории Git.

## Первый собственный прогон

```bash
./build/symmetry_cpu_cli examples/reflection.off \
  --output outputs/my-reflection \
  --sample-ratio 1 \
  --pair-threshold 0.08 \
  --verify-threshold 0.01
python3 tools/render_result.py outputs/my-reflection
```

Открыть `outputs/my-reflection/viewer.html`. Каталог результата должен быть новым или пустым: программа сохраняет существующие результаты и откажется их перезаписывать. Для повторного опыта выбрать другое имя, например `outputs/my-reflection-2`.

Для своей модели:

```bash
./build/symmetry_cpu_cli /путь/к/модели.off \
  --output outputs/my-model \
  --sample-ratio 0.2
python3 tools/render_result.py outputs/my-model
```

Поддерживаются обычный ASCII OFF и OBJ, включая OBJ-индексы со слешами и отрицательные индексы. Грани должны иметь согласованный winding, рёбра — не более двух смежных граней. Открытые границы разрешены. Многоугольники разбиваются веером; для вогнутых многоугольников заранее нужна корректная триангуляция. Цветные/расширенные варианты OFF не поддерживаются. Путь не переводится в нижний регистр.

Демо можно заново создать командой `python3 tools/make_demo.py`; файлы `examples/*.off` уже входят в рабочую папку.

## Параметры и их смысл

Полный список: `./build/symmetry_cpu_cli --help`.

| Параметр | По умолчанию | Что меняет |
|---|---:|---|
| `--sample-ratio` | 0.5 | Долю вершин, выбранных с весами по площади. Для большой модели сначала 0.05–0.2. |
| `--seed` | 42 | Случайную выборку и стартовые точки mean shift. Одинаковый вход/seed/параметры дают воспроизводимый результат в одной сборке. |
| `--smoothing` | 3 | Число проходов усреднения тензоров по соседям, не физический радиус. |
| `--prune` | 0.85 | Порог различимости главных кривизн; увеличение сохраняет больше точек. |
| `--pair-threshold` | 0.15 | Допуск на различие кривизн относительно их общей максимальной абсолютной величины. Увеличение даёт больше пар и шума. |
| `--bandwidth` | 0.08 | Радиус mean shift в нормализованном пространстве. Это непосредственно радиус, не старый MATLAB-параметр grid. |
| `--verify-threshold` | 0.025 | Допуск расстояния до поверхности как доля диагонали AABB. |
| `--subdivide` | 0 | 0–3 равномерных дробления граней с серединами рёбер. Каждый проход увеличивает число граней в 4 раза. |
| `--max-iterations` | 100 | Максимум итераций на траекторию mean shift; достижение лимита отражается в diagnostics и консоли. |
| `--max-clusters` | 20 | Число крупнейших по голосам гипотез, которые проверяются и экспортируются. |
| `--max-pairs`, `--max-votes` | 200000 / 600000 | Бюджеты: при превышении расчёт завершится с объяснением, а не обрежет данные незаметно. |
| `--no-patching` | выключен | Пропустить геометрическую проверку, сохранить только гипотезы. |

Если результатов нет, проверить число выбранных/отфильтрованных точек и пар. Для маленькой модели попробовать `--sample-ratio 1`, увеличить prune или pair-threshold. Если пар слишком много, уменьшить sample-ratio или pair-threshold. Более широкий bandwidth сливает близкие моды, но может ухудшить точность преобразования.

## Устройство нового ядра

После этапа 2 действуют следующие компоненты:

- `include/symmetry/`: общий API, типы, SoA/CSR и контракт backend;
- `src/core/`: геометрия, подготовка сетки и управление конвейером;
- `src/cpu/`: отдельные вычислительные этапы и CPU-backend;
- `src/io/`: чтение OFF/OBJ и экспорт;
- `src/app/main.cpp`: CLI;
- `tools/make_demo.py`, `tools/render_result.py`, `tools/viewer.html`: генератор моделей и viewer;
- `tests/`: геометрические, сквозные и контрактные проверки.

Конвейер:

1. Проверить индексы/координаты, удалить вырожденные грани, проверить ориентацию и manifold-рёбра, при необходимости дробить сетку.
2. Построить adjacency и нормали; получить edge-тензоры из двугранных углов, усреднить на вершинах и сгладить.
3. Решить 2×2 задачу собственных значений тензора в касательной плоскости: направления явно соответствуют kmin/kmax. Внешние библиотеки линейной алгебры не нужны.
4. Выбрать вершины без повторений с весами по площади и фиксированным RNG. Отбросить точки с почти равными кривизнами.
5. Перебрать пары выбранных точек с похожими кривизнами; убрать слишком близкие точки. Полный буфер S² не выделяется.
6. Каждая пара даёт два правильных жёстких преобразования с учётом неоднозначности знака главных направлений. При совместимости отражённых локальных кадров также даёт гипотезу зеркальной плоскости.
7. Провести mean shift отдельно для двух типов голосов, учитывать Epanechnikov-веса, visited, голосование и слияние. Счётчики 64-битные, хранение разреженное.
8. Проверить крупнейшие гипотезы в обоих направлениях через точное расстояние до треугольников с BVH. Проверяется также согласованность нормалей; неподвижные точки около оси/плоскости исключаются.
9. Выделить связные компоненты совпавших вершин по mesh adjacency и экспортировать обе стороны.

## Что исправлено или сознательно отличается от исторического пути

| Исторический путь | CPU-reference |
|---|---|
| Динамические Eigen-матрицы + MATLAB Engine | C++-массивы и векторы, без внешних обязательных зависимостей. |
| Непроверенная конверсия 0/1-based | Все индексы от 0; экспорт включает допустимую вершину 0. |
| Ремешинг по порогу площади | Опциональное равномерное conforming-дробление. Это другая стратегия, параметр явно отличается. |
| Выборка из групп граней, скрытая подвыборка источников пар | Area-weighted выборка вершин и полный перебор всех пар этой выборки. |
| Смешение направления и eigenvalue в MATLAB | Явная tangent eigen-задача с согласованными eigenpairs. |
| Допуски со знаком kmin | Неотрицательный общий допуск для обеих кривизн. |
| `t = q - p`, несмотря на вычисленный поворот | Полное `T(p) = R*p + t`, `t = q - R*p`. Обратное `Rᵀ*(p-t)`. |
| Определение отражения через подозрительную проверку направлений | Плоскость — серединный перпендикуляр пары; нормали и главные направления проверяются после отражения. |
| Углы Эйлера и маркер π | Явный тип. Для жёсткого преобразования descriptor = `[R/2 (9), (R*c+t-c)/boxSize (3)]`; для отражения `[n (3), (d+n·c)/boxSize]`. c — среднее координат вершин. |
| Reflection/rotation в одном пространстве | Два отдельных пространства голосов, поэтому типы не смешиваются усреднением. |
| Плотные MATLAB votes и списки членов | Разреженные 64-битные счётчики и списки индексов. |
| Рекурсия вокруг фиксированной целевой вершины, без R | Глобальная nearest-surface проверка полного T и T⁻¹, затем связные компоненты. |

У плоскости используется канонический знак нормали: максимальная по модулю компонента положительна. Усреднённая нормаль вновь нормализуется. Поворот после усреднения возвращается к ортонормальному правому кадру. Метрики нормализованы по диагонали и центру модели; старые численные настройки MATLAB не эквивалентны новым.

Эти изменения проверяются геометрическими fixtures, но ещё не представляют независимой экспертизы точного соответствия всем формулам статьи Митры.

## Результаты и воспроизводимость

| Файл результата | Содержимое |
|---|---|
| `mesh.off` | Фактическая сетка после подготовки/дробления; позволяет зафиксировать вход для следующих этапов. |
| `features.csv` | Координаты, кривизны, нормали, главные направления, valid/sample/prune маски. |
| `pairs.csv` | Индексы двух вершин каждой пары. |
| `votes.csv` | Тип голоса, полные R/t, плоскость и назначение в экспортированный кластер. -1 означает, что гипотеза не входит в сохранённые top-K. |
| `descriptors.csv` | Нормализованные координаты голосов и размерность, пустые колонки вне размерности. |
| `result.json` | Параметры, seed, диагностика, времена, сетка, выборка, пары, центры/преобразования, membership и обе стороны участков. |
| `viewer.html` | Самодостаточная визуализация, создаётся Python-командой после расчёта. |

`coverage` — суммарная доля vertex-area weights проверенных сторон, ограниченная 1. Это оценка, не точная площадь пересечения поверхностей. `rms` — RMS nearest-surface расстояний для принятых вершин стороны A в единицах модели. При отсутствии принятых точек RMS равен 0: смотреть также размеры сторон/coverage. Компоненты A/B выделяются независимо, однозначное соответствие между отдельными компонентами пока не строится.

Воспроизводимость проверена повторным запуском: JSON совпадает без `timings_ms`, CSV и OFF совпадают побайтно. Между различными компиляторами/архитектурами возможны численные различия. Результаты трёх демонстрационных запусков в `outputs/` не отслеживаются Git; генератор и модели отслеживаются.

## Проверки и границы этапа

Release-сборка и отдельная Debug-сборка с AddressSanitizer/UBSan прошли весь набор CTest (геометрия и сквозные сценарии). Ошибок памяти и undefined behavior на этих сценариях не обнаружено. JS-smoke также прошёл; страницы трёх демонстраций проверены по HTTP.

Автоматические проверки охватывают расстояния точка→треугольник, вырожденные треугольники, eigenpairs, известное отражение, известный поворот/сдвиг, изменение системы координат, частичную симметрию, небольшой шум, детерминизм, seed-dependent выборку, плоский участок без голосов, subdivision, OBJ-парсер, ошибки параметров/топологии и защиту существующих результатов. JS-smoke проверяет режимы рисования и события управления на минимальной модели DOM/canvas; фактический внешний вид браузера автоматически не снимался.

Демонстрации небольшие: reflection и rigid — по 132 вершины/256 граней, partial — 198/384. На первой проверке Release mean shift занял приблизительно 0.16–0.27 с; это не benchmark и не оценка скорости на больших моделях.

Ограничения:

- Scale != 1, другие исторические режимы и составные roto-reflections не реализованы.
- Согласованность winding обязательна; автоматическое исправление ориентации не выполняется. Качество кривизн на редких/неравномерных сетках требует проверки.
- Pairing пока O(S²), mean shift сравнивает с каждым голосом на каждой итерации. CPU-reference предназначен прежде всего для небольших/средних опытов; лимиты памяти не гарантируют короткого времени на больших входах.
- Дополнительно ограничены 20 000 mean-shift modes и 5 000 000 разреженных записей голосования. При превышении расчёт явно прекращается.
- Канонизация знака плоскости может разделять близкие голоса около границы смены доминирующей компоненты; это предмет дальнейшей проверки метрики.
- Экспортируются гипотезы с проверенными вершинами, но ложные частичные совпадения возможны. Ранжирование по support не гарантирует лучший геометрический ответ.
- Пока нет refinement/ICP, итогового symmetry graph, оценки статистической вероятности успеха или проверки на реальных моделях пользователя.

CUDA-код не добавлялся. Следующий шаг — использовать сохранённые fixtures для поэтапного сравнения будущих CUDA-kernels с этим CPU-reference.
